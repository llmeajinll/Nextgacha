# 장애 대응 정책

상태 표기와 문서 규칙은 [README](./README.md) 참고.

## 장애 등급
- 상태: 확정
- 정책:
  - **P1 (즉시)**: 결제·주문 불가, 돈과 주문이 어긋남(결제됐는데 주문 없음, 환불됐는데 재고·포인트 미복구), 개인정보 노출, 남의 데이터 수정 가능
  - **P2 (당일)**: 로그인 불가, 관리자 주문 처리 불가, 주요 페이지(홈·상품 상세·장바구니) 500
  - **P3 (다음 작업 때)**: 일부 화면 깨짐, 통계·검색 같은 부가 기능 오류
- 이유: 혼자 운영하므로 "무엇부터 볼지"만 정해 두면 된다. 돈과 개인정보가 걸린 것이 항상 먼저다.
- 변경 이력: 2026-11-10 신설, 2026-11-10 확정

## 감지
- 상태: 확정
- 정책: 시스템 에러는 Sentry로 모으고, P1에 해당하는 실패(결제 취소 실패, 환불 DB 실패, 결제 대사 불일치)는 관리자 카카오톡으로 바로 알린다. 방법은 [에러 알림](./engineering.md#에러-알림).
- 코드: 미구현. `src/app/api/postPaymentsConfirm/route.ts` `cancelPayment`, `src/app/api/postCheckToSending/route.ts` `refundOrder`
- 변경 이력: 2026-11-10 신설, 2026-11-11 확정 (Sentry + 관리자 카카오톡)

## 대응 순서
- 상태: 확정
- 정책:
  1. 등급 판단: 결제·개인정보가 걸렸는지부터 확인
  2. 직전 배포 이후 시작됐으면 [롤백](./deploy.md#롤백) 먼저
  3. P1 결제 장애면 Toss 대시보드 결제 내역과 `orderColl`을 비교해서 어긋난 건을 목록으로 만든다 ([결제 불일치 처리](#결제-불일치-처리))
  4. 원인 수정은 PR로, 재발 방지는 [사후 기록](#사후-기록)에 남긴다
- 변경 이력: 2026-11-10 신설, 2026-11-10 확정

## 결제 불일치 처리
- 상태: 확정
- 정책: 경우별로 아래처럼 처리하고, 처리한 건은 `errorColl` 기록에 처리 결과를 덧붙인다.
  - **결제됨 + 주문 없음** (`[결제 취소 실패]` 기록): Toss 대시보드에서 해당 결제를 취소하고 구매자에게 안내한다. 주문을 수동으로 만들지 않는다(재고·한도 검증을 다시 거쳐야 함).
  - **결제 취소됨 + 주문 정리 안 됨** (`[환불 DB 처리 실패]` 기록): 주문 상태를 `환불`로 바꾸고 재고, `user.keep`, 사용 포인트를 `refundOrder`와 같은 순서로 직접 복구한다.
  - **주문 있음 + 결제 없음**: 정상 흐름에서는 생길 수 없다(Toss 승인 후에만 주문 생성). 발견하면 P1로 원인부터 찾는다.
- 도구: 지금은 수동(Atlas·Toss 대시보드)으로 처리한다. 같은 불일치가 두 번 이상 생기면 그때 복구 스크립트(`scripts/`)를 만든다.
- 코드: `src/app/api/postPaymentsConfirm/route.ts` `cancelPayment`, `src/app/api/postCheckToSending/route.ts` `refundOrder`, [결제 대사](./payments.md)
- 변경 이력: 2026-11-10 신설, 2026-11-10 확정

## 백업·복구 목표
- 상태: 확정
- 정책: 데이터 손실은 최대 24시간(RPO), 복구는 6시간 안(RTO). 하루 한 번 `mongodump` 백업으로 맞춘다([환경 분리와 백업](./data.md#환경-분리와-백업)). 주문·결제 데이터는 Toss 내역으로 일부 복원할 수 있다.
- 변경 이력: 2026-11-10 신설, 2026-11-11 확정 (RPO 24시간, RTO 6시간)

## 사용자 공지
- 상태: 확정
- 정책: P1·P2 장애 동안 공지사항(`/notice`)에 글을 올린다. 결제 장애 때는 환경변수 하나로 결제 버튼을 막는 스위치를 둔다. 장애 알림은 관리자 카카오톡으로 받는다([감지](#감지)).
- 구현 메모: 스위치는 서버(`postPaymentsConfirm`)에서도 확인해야 버튼을 우회한 요청까지 막는다. Vercel 환경변수를 바꾸면 재배포가 필요하다.
- 코드: 미구현
- 변경 이력: 2026-11-10 신설, 2026-11-11 확정 (공지사항 글, 결제 차단 스위치)
