# 디자인·UX 정책

상태 표기와 문서 규칙은 [README](./README.md) 참고. 색·폰트·간격 같은 **실제 값**은 [디자인 시스템](../design-system.md)에 있고, 이 문서는 그 값을 언제 어떻게 쓸지만 정한다. 코드 작성 규칙은 `.claude/rules/styling.md`.

## 아이콘
- 상태: 확정
- 정책:
  - 아이콘은 `pixelarticons/react`만 쓴다. PNG 아이콘이나 직접 그린 SVG path를 새로 만들지 않는다.
  - 클릭되는 아이콘은 `shared/ui` `ImgBtn`(`<button>`)으로 만든다. 표시만 하는 아이콘은 컴포넌트를 바로 쓰고 `aria-hidden`.
  - 켜짐/꺼짐이 있는 아이콘(좋아요, 별점)은 색으로 상태를 나눈다: 켜짐 `blue1`, 꺼짐·비활성 `slate[300]`. pixelarticons에는 채워진 버전이 없다.
- 예외: 일러스트(배송 트럭, 영수증, 리뷰 도장, 이벤트 배너, 티켓 배경), 기본 상품 이미지, 카카오 로그인 버튼은 이미지로 둔다.
- 코드: `src/shared/ui/ImgBtn/ImgBtn.tsx`, `src/shared/ui/ImgBtn/imgBtn.css.ts`
- 변경 이력: 2026-11-10 신설

## 색 사용
- 상태: 확정
- 정책:
  - 새 색은 `theme.css.ts`에 토큰을 먼저 추가하고 쓴다. hex 값을 컴포넌트에 직접 쓰지 않는다.
  - 흰 글자를 올리는 배경은 `slate[600]` 이상 또는 `ink[500]` 이상 (대비 4.5:1).
  - `blue1`(#75C3FE)은 흰 배경 위 글자 대비가 낮아서, 픽셀 폰트 라벨(예: 관리자 `DASHBOARD`, `ADD PRODUCT`)이나 아이콘·테두리·배경에만 쓴다. 본문·안내 문구에는 쓰지 않는다.
- 이유: 토큰에 없는 색이 10종 넘게 직접 쓰이고 있다 ([디자인 시스템 1.2](../design-system.md)).
- 변경 이력: 2026-11-10 신설, 2026-11-10 확정

## 접근성 기본
- 상태: 확정
- 정책:
  - 클릭되는 요소는 `<button>`이나 `<a>`로 만든다. `<div onClick>`, `<img onClick>`을 새로 쓰지 않는다.
  - 아이콘만 있는 버튼에는 `aria-label`, 상태가 있는 버튼에는 `aria-pressed`(토글)나 `aria-checked`(체크박스)를 단다.
  - 키보드 포커스가 보여야 한다. `outline: none`을 쓰면 대신할 포커스 스타일을 함께 둔다.
  - 이미지에는 `alt`를 넣는다(장식용이면 `alt=""`).
  - 모달은 Esc로 닫히고, 열리면 모달 안으로 포커스가 들어간다.
  - 키보드만으로 장바구니 담기 → 결제까지 갈 수 있어야 한다.
- 이유: 아이콘 교체 때 `ImgBtn`·`HeartBtn`·`ToggleBtn`은 버튼으로 바꿨지만, 드롭다운 열기(`div onClick`) 같은 곳이 남아 있다. `AlertModal`, `ReviewModal`, `AddressModal`에는 Esc 처리가 없고, `alt`가 없는 `<img>`가 3곳 있다.
- 코드: 남은 예 `src/features/cart/ui/DropDown.tsx` (`dropdownContainer`), `src/shared/ui/AlertModal.tsx`
- 변경 이력: 2026-11-10 신설, 2026-11-10 확정 (`ux.md` 접근성 기본 병합)

## 문구
- 상태: 확정
- 정책: 영어는 픽셀 폰트 장식 라벨(BUY, CART, SEARCH...)에만 쓰고, 설명·안내·에러는 한국어 합니다체로 쓴다(예: "로그인 후 좋아요를 누를 수 있습니다.").
- 참고: 에러 문구 내용(무엇이 안 됐는지 + 할 일)은 [에러 문구와 입력 보존](./ux.md#에러-문구와-입력-보존)을 따른다.
- 변경 이력: 2026-11-10 신설, 2026-11-11 확정 (영어는 장식 라벨만, 합니다체)

## 지원 화면 크기
- 상태: 확정
- 정책: 모든 사용자 페이지를 360px 폭부터 지원한다. 순서는 상품 상세 → 장바구니 → 결제 → 홈, 그다음 나머지 사용자 페이지. 관리자 페이지(`/manager`)는 데스크톱만 지원한다.
- 이유: 지금은 데스크톱 고정폭(1314px)만 지원하고 미디어 쿼리가 없다. 계획은 [디자인 시스템 3.4](../design-system.md#34-모바일-대응-계획).
- 코드: 미구현
- 변경 이력: 2026-11-10 신설, 2026-11-11 확정 (사용자 페이지 전체, 360px부터)
