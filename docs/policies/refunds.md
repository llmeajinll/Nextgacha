# 취소/환불/반품 정책

상태 표기와 문서 규칙은 [README](./README.md) 참고.

## 구매자 주문 취소
- 상태: 미정
- 정책: 미정. 추천안은 `상품 확인중`인 주문만 구매자가 직접 취소할 수 있게 하는 것. 처리는 관리자 환불(`refundOrder`)과 같은 흐름(Toss 취소 → 재고·keep·usedPoint 복구)을 재사용한다.
- 예외: 미정 (예약 상품 취소 허용 여부)
- 이유: 지금은 관리자가 거절할 때만 환불되므로, 구매자는 문의 말고는 취소할 방법이 없다.
- 코드: 미구현. 재사용 대상 `src/app/api/postCheckToSending/route.ts:16` `refundOrder`
- 변경 이력: 2026-11-09 신설

## 배송 후 반품/교환 (청약철회)
- 상태: 미정
- 정책: 미정. 법정 기준은 상품을 받은 날부터 7일 이내 청약철회 가능 (전자상거래법 제17조). 단순 변심 반품 배송비는 구매자 부담이 기본 (제18조).
- 예외: 미정 (개봉한 가챠 상품을 "가치가 현저히 감소한 경우"로 보고 제외할지. 제외하려면 사전 고지 필요, 제17조 2항·6항)
- 이유: 지금은 `배송중`이나 `배송 완료` 상태에서 환불하는 경로가 없다.
- 결정할 것:
  - 반품 신청 → 회수 → 검수 → 환불 상태를 추가할지 (`반품 요청`, `반품 완료` 등)
  - 반품 배송비 차감 방식 (환불 금액에서 공제 / 별도 결제)
  - 이미 지급한 적립 포인트(`addPoint`) 회수 방법, 포인트를 이미 써서 잔액이 모자랄 때 처리
  - 반품 수량만큼 재고 복구 여부 (재판매 불가 상품이면 복구 안 함)
- 코드: 미구현. 적립 지급 `src/app/api/postSendingToFinish/route.ts:29`
- 변경 이력: 2026-11-09 신설

## 부분 환불
- 상태: 미정
- 정책: 미정. 추천안은 처음에는 주문 단위 전체 환불만 지원하고, [배송 후 반품/교환](#배송-후-반품교환-청약철회) 정책을 정할 때 같이 결정하는 것.
- 이유: 부분 환불은 배송비 재계산(5만 원 무료배송 기준이 깨질 때), 포인트 분배 규칙이 함께 필요하다.
- 코드: 미구현 (`refundOrder`는 주문 전체만 처리)
- 변경 이력: 2026-11-09 신설
